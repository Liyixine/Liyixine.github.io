全栈开发总结

发表于2025-12-15|更新于2025-12-15
|总字数:760|阅读时长:2分钟|浏览量:

1. 项目背景 (The “Why”)

为了探索 LLM 在长期记忆领域的应用，我构建了 Then.。不同于普通的聊天机器人，”Then.” 旨在通过 RAG（检索增强生成）技术，将用户的碎片化对话和文档转化为可被索引的“记忆”，实现与“过去的自己”对话。

  • 产品理念： 取意“当时只道是寻常”，利用 Promise.then() 的异步隐喻，连接过去的数据与未来的交互。

2. 技术架构与选型 (Architecture)

采用 Monorepo 结构管理代码，确保类型定义 (TypeScript Interfaces) 在前后端复用。

  • 前端: React + Vite + Tailwind CSS (极速构建，原子化样式)
  • 后端: Node.js + Express (灵活的 API 控制)
  • AI/数据:
    • Orchestration: LangChain (处理 Prompt 模板与链式调用)
    • Vector DB: Pinecone (高性能向量存储)
    • Metadata DB: MongoDB (存储结构化的用户配置与对话历史)
  • Auth: Clerk (现代化的身份验证解决方案)
  • DevOps: Vercel (Frontend + Serverless) + Render (Backend API)

3. 核心工程挑战与解决方案 (Engineering Challenges)

挑战一：分布式环境下的 Webhook 可靠性问题

  • 问题： 生产环境中，Render 的后端服务在无流量时会休眠。当 Clerk 触发 user.created Webhook 时，后端可能因唤醒延迟或冷启动失败而丢失请求，导致用户数据不同步。
  • 解决方案： 实施架构解耦。我利用 Vercel Serverless Function 的“永不休眠”特性作为 Webhook 的接收端，负责直接写入 MongoDB。同时在后端 API 层实现兜底逻辑（Lazy Creation），确保数据一致性。

挑战二：后端休眠重启动对用户体验的影响

  • 问题： 免费层级的后端服务有约 50 秒的冷启动时间，严重阻碍用户进入应用。
  • 解决方案： 实施**“预测性预热” (Predictive Pre-warming)** 策略。
    • 在用户访问 Landing Page 介绍页时，前端静默发送 fetch 请求唤醒后端。
    • 在用户输入账号密码的间隙，再次触发心跳检测。
    • 这利用了用户浏览和操作的“时间差”，将冷启动对用户的影响降至最低。

挑战三：全栈开发中的环境隔离与配置管理

  • 问题： 在 TypeScript Monorepo 中，遇到了 CommonJS/ESM 模块兼容性问题，以及开发环境与生产环境的环境变量管理混乱。
  • 解决方案：
    • 标准化 tsconfig.json 配置，统一模块解析策略。
    • 严格区分 dev 与 prod 环境变量，并在 Vercel/Render 后台进行加密管理。
    • 重构代码结构，将 API Client 封装为单例，自动适配不同环境的 Base URL。

4. 产品思维与 UI/UX 迭代

  • 从“能用”到“好用”： 最初版本仅有基础功能。后续引入 Figma 进行原型设计，实现了 Markdown 渲染、代码高亮、消息气泡自适应布局，以及基于 Framer Motion 的微交互动画。
  • 品牌重塑： 确立了以“白色/极简/衬线体”为主的视觉语言。
